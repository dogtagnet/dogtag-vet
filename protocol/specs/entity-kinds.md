# Entity kinds

An entity registered in `EntityRegistry` carries a set of kinds.
Kinds describe what a business is.
They are a record only: a kind grants no right, and no contract branches on one.
The rights to issue records, hold `ISSUER_ROLE`, run an operator whitelist or verify consent stay in their own access lists, controlled by the DogTag protocol.
This document and `entity-kinds.json` are the single source of truth for the bit numbers.

## The mask

- On chain the set is one `uint256` mask, one bit per kind.
- The bit number equals the kind's ordinal in the contract's `EntityKind` enum, so entities registered before EntityRegistry version 2 need no migration.
- A mask is written as a decimal string in JSON, because a `uint256` does not fit in a JSON number.

| Bit | Mask value | Public id | Contract enum member |
|---|---|---|---|
| 0 | 1 | reserved, never set | `None` |
| 1 | 2 | `VET` | `Vet` |
| 2 | 4 | `GOVERNMENT` | `Government` |
| 3 | 8 | `GROOMER` | `Groomer` |
| 4 | 16 | `BOARDING` | `Boarding` |
| 5 | 32 | `DAYCARE` | `Daycare` |

A vet that also grooms holds mask 10, bits 1 and 3.

## Rules

1. A bit number is never reused and never renumbered.
2. A new kind takes the next free bit, by a change to `entity-kinds.json` and this document.
   The contract needs no upgrade for it: it accepts every bit from 1 to 255.
3. Bit 0 is reserved.
   The contract rejects a mask with bit 0 set and rejects a zero mask (`InvalidKinds`).
4. Clients ignore bits they do not know and never fail on them, because kinds grant no rights.
   A client that sees only unknown bits shows the entity without a kind label.
5. The primary kind is the lowest set bit that the client knows.
   It is what the single-valued `kind` field of the directory API carries.
   When no set bit is known there is no primary kind.
6. The public id is the upper-case string in the table.
   Ids are compared exactly and are never localised; `label` is the English display name and clients may localise it.
7. A client that builds a mask from ids rejects an unknown id, an empty list and a duplicate id.
   Order of the input list does not matter.

## Contract behaviour worth knowing

- `kindsOf(account)` returns the stored mask.
  When no mask was ever written (every entity added before version 2) it returns `1 << uint8(kind)` from the legacy `kind` field.
- `registerEntity` stores the lowest set bit as the legacy `kind` when that bit names an enum member (bits 1 to 5), and `None` otherwise.
  A mask holding only bits above 5 is therefore valid and has legacy kind `None`.
- `EntityRegistry` emits `EntityKindsSet(account, previousKinds, kinds)` whenever a mask is written.
  See `events.md`.

## Shared helper and vectors

- TypeScript helper: `packages/dogtag-standard-ts/src/entityKinds.ts` (`entityKindsFromMask`, `maskFromEntityKinds`, `primaryEntityKind`, `ENTITY_KINDS`).
- Conformance vectors: `entity-kinds-vectors.json`, generated by `pnpm gen-entity-kinds-vectors` in the package and checked by an independent, hand-written test (`test/entity_kinds_vectors.test.ts`).
  Other implementations, such as the Swift client, mirror the same vectors.
