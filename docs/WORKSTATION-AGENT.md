# DogTag workstation playbook for the deployment agent (FINAL revision 2, 2026-09-25, adds the operator wallet funding of WP4.19; revision 1 of 2026-09-22: verified against the release tips protocol 3011e89, vet 2af957e, admin ff65729, ios 0b7bd19 by the WP4.17 phase C evaluation)

## For Kenneth (human summary)

Give this file to the AI coding agent on the Ubuntu workstation and tell it: "Deploy DogTag by following WORKSTATION-AGENT.md; ask me for every value marked ASK KENNETH."
The agent works through the steps in order, runs the verification command at the end of each step, and stops on any failure instead of improvising.
It asks you only for values that exist nowhere else: hostnames, wallet addresses, SMTP details, the Cloudflare tunnel token, and confirmation before each on-chain step.
It never writes a secret into a committed file; secrets go into Kubernetes Secrets, Foundry keystores or git-ignored local files, each named in the step.
The whole run takes about two hours plus the time you spend answering; the acceptance run at the end needs you and the phone.
Everything here targets the ROAX testnet (chain id 135) with the PLASMA native token and the RUSD development stablecoin, behind Cloudflare Tunnel at `admin.dogtag.roax.net` and `vet.dogtag.roax.net`.

## For the agent: rules

- Execute the steps in order; do not skip, reorder or merge them.
- Every step ends with a VERIFY command and its expected output; if the output differs, STOP, show Kenneth the output, and wait; never retry an on-chain write on your own.
- ASK KENNETH lines are questions you ask him in chat; write the answer only where the line says (an environment variable for the current shell, a values file that is not committed, a Kubernetes Secret, or a Foundry keystore); echo nothing sensitive back.
- Before each on-chain step (marked CHAIN), show Kenneth the exact command and the addresses it uses and wait for "go".
- Never run `git push`, never commit `values-*.yaml` files that carry real values, never print a private key, never paste a private key into any file; keystores are created with `cast wallet import --interactive`, which reads the key from Kenneth's terminal, not from you.
- Record every address, block number and hash you obtain in `~/dogtag/DEPLOYMENT-RECORD.md` (a local file, not committed) as you go; later steps read from it.
- Load is not a concern on the workstation; run gates as written.

## Secrets and values map

| Value | Where it goes | Source |
|---|---|---|
| ADMIN private key | Foundry keystore `dogtag-admin` (step 3) | Kenneth types it at the interactive prompt |
| PUBLISHER private key | Foundry keystore `dogtag-publisher` (step 3) | same |
| ADMIN, PUBLISHER, CUSTODIAN, CLINIC OPERATOR addresses | `~/dogtag/DEPLOYMENT-RECORD.md` and shell variables | ASK KENNETH (step 3) |
| SMTP host, port, user, password, sender | Kubernetes Secrets `dogtag-admin-secrets` and `dogtag-vet-secrets` (step 6) | ASK KENNETH (step 6) |
| Kenneth's admin sign-in email | Secret `dogtag-admin-secrets` key `ADMIN_EMAILS` | ASK KENNETH (step 6) |
| AUTH_SECRET (two values), NEXTAUTH_SECRET, VAPID keys | the same Secrets | generated by the agent (`openssl rand -base64 32`, `npx web-push generate-vapid-keys`) |
| Cloudflare tunnel token | Secret `cloudflared-token` (step 7) | ASK KENNETH (step 7) |
| Contract addresses and deploy blocks | `values-admin.yaml`, `values-vet.yaml` (git-ignored copies), `~/dogtag/DEPLOYMENT-RECORD.md` | steps 4 and 8 |
| RUSD address | `values-vet.yaml` key `env.TOKEN_RUSD_ROAX_ADDRESS` | step 4 |
| Phone anchor (registry address, RPC, explorer, chain id) | `dogtag-ios/Config/Environment.xcconfig` on the Mac (git-ignored) | step 11, Kenneth on the Mac |
| App Store Connect API key | `~/.appstoreconnect/private_keys/AuthKey_<KEYID>.p8` on the Mac; key id and issuer id as shell variables | Kenneth on the Mac |

## Step 0: preconditions

ASK KENNETH: the git remote URL prefix for the four repos (dogtag-protocol, dogtag-admin, dogtag-vet, dogtag-ios) and the release tag or branch to check out.
ASK KENNETH: confirm the workstation is Ubuntu 22.04 or 24.04 with sudo and outbound internet, and that no other Kubernetes or Docker is installed.
VERIFY: `lsb_release -ds && nproc && free -g | head -2 && df -h / | tail -1` shows Ubuntu, at least 8 CPUs, 16 GB memory, 100 GB free.

## Step 1: install the tools

```
sudo apt-get update && sudo apt-get install -y git curl ca-certificates gnupg build-essential jq
curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER
curl -sfL https://get.k3s.io | sh -
mkdir -p ~/.kube && sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config && sudo chown $USER ~/.kube/config
curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt-get install -y nodejs && sudo corepack enable
curl -L https://foundry.paradigm.xyz | bash && ~/.foundry/bin/foundryup
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb -o /tmp/cloudflared.deb && sudo dpkg -i /tmp/cloudflared.deb
```
Note: `docker` group membership applies to new shells; open a new shell or use `sg docker -c '<command>'` for the docker commands below.
VERIFY: `docker version --format '{{.Server.Version}}' && kubectl get nodes && helm version --short && node -v && pnpm -v && ~/.foundry/bin/forge --version && cloudflared --version` prints a version for each and one node in state Ready.

RUSD (CHAIN):

## Step 6: namespace, Mongo, Secrets

ASK KENNETH: SMTP host, port, user, password and sender address; his admin sign-in email.
```
kubectl create namespace dogtag
kubectl apply -n dogtag -f ~/dogtag/dogtag-admin/deploy/k3s/mongo.yaml
VAPID=$(npx --yes web-push generate-vapid-keys --json)
kubectl create secret generic dogtag-admin-secrets -n dogtag \
  --from-literal=AUTH_SECRET=$(openssl rand -base64 32) --from-literal=NEXTAUTH_SECRET=$(openssl rand -base64 32) \
  --from-literal=ADMIN_EMAILS=<KENNETH EMAIL> \
  --from-literal=SMTP_HOST=<HOST> --from-literal=SMTP_PORT=<PORT> --from-literal=SMTP_USER=<USER> --from-literal=SMTP_PASSWORD=<PASSWORD> --from-literal=SMTP_FROM=<SENDER> \
  --from-literal=GOOGLE_CLIENT_ID= --from-literal=GOOGLE_CLIENT_SECRET= \
  --from-literal=VAPID_PUBLIC_KEY=$(echo $VAPID | jq -r .publicKey) --from-literal=VAPID_PRIVATE_KEY=$(echo $VAPID | jq -r .privateKey) --from-literal=VAPID_SUBJECT=mailto:<KENNETH EMAIL>
kubectl create secret generic dogtag-vet-secrets -n dogtag \
  --from-literal=AUTH_SECRET=$(openssl rand -base64 32) \
  --from-literal=EMAIL_SERVER='smtp://<USER>:<PASSWORD>@<HOST>:<PORT>' --from-literal=EMAIL_FROM=<SENDER>
```
Type the SMTP values into the commands directly; never save them in a file.
VERIFY: `kubectl get pods -n dogtag` shows mongo-0 Running; `kubectl get secret -n dogtag` lists both secrets.

## Step 7: Cloudflare Tunnel

ASK KENNETH: to create, in Cloudflare Zero Trust (Networks, Tunnels), a tunnel named `dogtag-workstation` with two public hostnames: `admin.dogtag.roax.net` to `http://dogtag-admin-web.dogtag.svc.cluster.local:80` and `vet.dogtag.roax.net` to `http://dogtag-vet-web.dogtag.svc.cluster.local:80`, and to paste the tunnel token in chat.

## Step 10: onboard the clinic (Kenneth in the browser, agent verifies)

1. Kenneth applies at `https://admin.dogtag.roax.net/apply` with "Platform base URL" `https://vet.dogtag.roax.net`.
2. Kenneth approves at `/admin/applications/<id>` with the ADMIN wallet: the stepper adds the entity, deploys the clone, initialises delegation, grants the issuer role, whitelists the CLINIC OPERATOR address and, in the same operator step, offers "Fund operator wallet" (1 PLASMA from the ADMIN wallet, the `OPERATOR_BASE_PLASMA` default); Kenneth sends it so the clinic never starts with an empty wallet. ASK KENNETH for the clone address; record it.
3. CHAIN: `cast send <CLONE> --value 50ether --rpc-url https://devrpc.roax.net --legacy --account dogtag-admin` (the clone's gas refund pool).
4. Kenneth signs in at `https://vet.dogtag.roax.net/sign-in` (the first real sign-in becomes the clinic owner), completes `/setup` with the CLINIC OPERATOR wallet in MetaMask on chain 135, then Settings: clinic profile, services and availability, practitioner profile, receiving address on the ROAX (testnet) row.
5. CHAIN (test balances): `cast send <RUSD> "mint(address,uint256)" <PHONE WALLET> 1000000000 --rpc-url https://devrpc.roax.net --legacy --account dogtag-admin` (1000 RUSD); ASK KENNETH for the phone wallet address first.
VERIFY: `curl -s https://admin.dogtag.roax.net/v1/entities | jq '.entities[0] | {name, cloneAddress, platformBaseUrl}'` shows the clinic with its clone and vet URL; `cast call <CLONE> "operators(address)(bool)" <CLINIC OPERATOR> --rpc-url https://devrpc.roax.net` prints true.
VERIFY: `cast balance <CLINIC OPERATOR> --rpc-url https://devrpc.roax.net --ether` is at least 1 (the operator wallet was funded); the vet portal's Settings card "My issuance wallet" shows the same balance with no low-balance warning.
